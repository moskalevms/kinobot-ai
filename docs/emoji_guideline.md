# Эмодзи-гайдлайн бота («1 эмодзи = 1 смысл»)

Статус: нормативный документ для всех пользовательских текстов Kinobot
(кнопки, списки, карточки, ошибки, свободные ответы LLM). Источник — задача
B6 бэклога `backlog/backlog_2026-09-16_uiux_telegram.md` и отчёт
исследования UI/UX (§2.3, §5 P1.13, `docs/research/`). Регрессионная защита
запретного списка — `tests/test_emoji_guideline.py`.

## Принцип

**1 эмодзи = 1 смысл.** Каждый пользовательский эмодзи имеет единственное
закреплённое значение из таблиц ниже. Запрещено:

- использовать один и тот же эмодзи в двух разных смыслах;
- вводить новый эмодзи, не внесённый в гайдлайн;
- использовать декоративные эмодзи «для настроения» без закреплённого смысла.

## Область применения

Гайдлайн обязателен для **пользовательских текстов**: сообщения бота,
кнопки (reply и inline), списки выдачи, карточки фильмов, сообщения об
ошибках, тексты, формируемые LLM по промптам `src/prompts/*.txt`, а также
пользовательские тексты веб-интерфейса.

**Вне области**: логи разработчика (`logger.*` — там допустимы ✅ ❌ ⚠️ 🔧
как маркеры статуса), комментарии в коде, служебная документация.

## Кнопки возврата: два стиля (⬅️ контекстный / 🏠 хаб)

Правило введено задачей C2 бэклога
`backlog/backlog_2026-10-06_bot-back-button.md` (изменение
`unify-back-button-emoji-c2`) по выводу исследования
`docs/research/bot-back-button-2026-10-06.md`: пользователю важно различать
«шаг назад внутри раздела» и «выход в центр навигации», поэтому два служебных
символа (⬅️ и 🏠) закреплены за ДВУМЯ разными смыслами возврата.

- **🏠 — выход в хаб.** ЛЮБАЯ кнопка с `callback_data` = `menu:main`
  (единственный маршрут главного меню — ветка `main` обработчика префикса
  `menu:` в `src/telegram_bot.py`) подписывается «🏠 Меню»: общая константа
  `MENU_BUTTON_TEXT` (`src/dialogue_manager.py`, B1). Исключений нет — если
  кнопка ведёт в хаб маршрутом `menu:main`, её подпись начинается с 🏠.
- **⬅️ — контекстный возврат** в пределах потока или раздела: к списку выдачи
  (`back:list`), к карточке фильма из панели оценки (`info:{id}`, «⬅️ Назад»)
  и к родительскому подменю того же раздела — возврат по сегменту
  СОБСТВЕННОГО префикса (`top:menu` в подменю топов, `genre:menu` в меню
  жанров). Подписи — «⬅️ К списку» и «⬅️ Назад».

Стиль определяется маршрутом (`callback_data`), а не тем, какой текст рисует
обработчик: диспетчеризация бота идёт по `callback_data` (правило 4), поэтому
унификация подписей **не меняет** ни `callback_data`, ни префиксы таблицы
`_CALLBACK_ROUTES`, ни состав обработчиков. Вводить новые callback-сущности
или менять маршруты ради эмодзи запрещено (критерий приёмки C2: «НЕ менять
callback_data — только тексты»).

Граница правила: регулируются только КНОПКИ ВОЗВРАТА. Кнопка «🎬 Карточка»
подтверждения фидбека (B5) идёт тем же маршрутом `info:{id}`, но возвратом не
является — это переход к карточке фильма (смысл 🎬 «фильм/киноконтент»),
поэтому в инвентарь она не входит и её подпись не обязана начинаться с ⬅️.

### Известное остаточное расхождение (документированный долг)

Обработчики `top:menu` (`_handle_top_callback`) и `genre:menu`
(`_handle_genre_callback`) тоже рисуют главное меню, то есть ПО НАЗНАЧЕНИЮ
это выход в хаб, но подписи кнопок остаются «⬅️ Назад»: возврат идёт
собственными сегментами префиксов `top:`/`genre:`, а не маршрутом `menu:main`.
Привести их к 🏠 можно только сменой `callback_data` (или новым маршрутом),
что запрещено скоупом C2. Расхождение зафиксировано здесь как
документированный долг, а не дефект: формальный критерий правила
(«🏠 ⇔ `menu:main`») выполнен во всех клавиатурах бота. Условие снятия долга —
отдельная задача, переводящая возвраты top/genre на маршрут хаба вместе с
контракт-тестами маршрутов (`tests/test_callback_routes_t4.py`,
`tests/test_menu_callbacks_b8.py`, `tests/test_genre_keyboard_t6.py`,
`tests/test_phase1_verification_b9.py`).

Регрессионная защита правила — `tests/test_emoji_guideline.py`: документные
проверки формулировки/инвентаря и инвентарь-тест по РЕАЛЬНО собранным
клавиатурам (каждая кнопка с `callback_data` = `menu:main` начинается с 🏠,
каждая контекстная — с ⬅️).

## Правила употребления

1. **≤ 1 эмодзи на строку списка.** Исключение — строка-вердикт карточки:
   в ней допустимы функциональные маркеры данных (⭐ рейтинг, 🍅 критики),
   т.к. они несут разные закреплённые смыслы, а не декор.
2. **Позиция — начало или конец фразы**, никогда в середине предложения.
   Эмодзи в начале строки работает как маркер категории.
3. **Доступность.** Скринридеры озвучивают название каждого эмодзи
   («лицо, рыдающее от смеха»). Поэтому: не дублировать эмодзи смысл,
   уже выраженный словами; не ставить два эмодзи подряд; не использовать
   эмодзи как единственного носителя смысла (рядом всегда текстовая подпись).
4. **Кнопки.** Эмодзи — часть текста кнопки. С задачи B8 меню полностью
   inline: диспетчеризация идёт по `callback_data` (префиксы `menu:`/`top:`),
   сравнения текста сообщения с подписями кнопок из кода удалены — правка
   эмодзи в подписи больше не ломает маршрутизацию, но смысл эмодзи остаётся
   закреплённым (таблицы выше), а подписи проверяются тестами. Для кнопок
   возврата/выхода стиль эмодзи определяется маршрутом — см. подраздел
   «Кнопки возврата: два стиля (⬅️ контекстный / 🏠 хаб)» (C2).
5. **Ошибки.** Только ⚠️ в начале текста; сообщение об ошибке обязано
   предлагать действие (кнопка 🔄 «Повторить» — задача B7).
6. **Свободные ответы LLM.** Промпты (`src/prompts/*.txt`) содержат
   инструкцию: не использовать эмодзи из списка «Избегать», соблюдать
   «1 эмодзи = 1 смысл» и правило позиции. Промпты — источник поведения
   (AGENTS.md): меняя набор эмодзи, меняйте сначала гайдлайн, потом промпты.

## Как применять (чек-лист для новой кнопки/текста)

1. Нужен ли эмодзи вообще? Текст без эмодзи — допустимая норма.
2. Есть ли у смысла эмодзи в таблицах «Ядро»/«Добавить»/«Служебные»?
   Нет — сначала добавьте строку в гайдлайн (PR), потом в код.
3. Стоит ли эмодзи в начале или конце фразы? Ровно один на строку?
4. Не дублирует ли он смысл слов рядом (скринридер прочитает оба)?

## Единая точка констант

Модуль констант эмодзи в `src/` намеренно не создавался в B6, чтобы не
конфликтовать с B8 (перевод меню на inline-кнопки). B8 реализован БЕЗ
отдельного модуля (например `src/emoji.py`): по design.md D6 изменения
`add-inline-menu-callbacks` «единая точка» — именованные константы подписей
кнопок и текстов меню в `src/telegram_bot.py` (общие для команд и
callback-маршрутов `menu:`/`top:`) плюс прецедент локальной константы
`RT_BADGE_EMOJI` в `src/dialogue_manager.py`. Источник правды о смыслах
эмодзи — этот документ; консолидация констант в единый модуль возможна
в будущем отдельной задачей.

T10 (`add-single-source-mood-genre-constants-t10`): словарь подписей
кнопок настроения `MOOD_BUTTON_LABELS` и данные запросов жанров
(`GENRE_MENU_NAMES`, `GENRE_QUERY_TEMPLATE`, `GENRE_QUERIES`) перенесены
из `src/telegram_bot.py` в `src/dialogue_manager.py` — единый источник
живёт рядом со словарями настроений/жанров `mood_triggers`/`mood_to_genre`,
что исключает рассинхрон кнопок и детерминированных маршрутов. Guard
