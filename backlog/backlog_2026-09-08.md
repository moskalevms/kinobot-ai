## Epic A (P0): «бесплатные критики» из уже получаемых данных kinopoisk.dev

> Ценность: критический сигнал в ранжировании и выдаче **без новых API, ключей и затрат** — `selectFields=rating,votes` уже возвращает `filmCritics` (`src/kinopoisk_client.py:79-80`), код его игнорирует. Ограничение: полезное покрытие ~2% базы (21k фильмов) — совпадает с профилем выдач (англоязычный приоритет).

- [x] **A1. Учёт `rating.filmCritics` в `get_weighted_rating`** — 0.5 дня; зависит: —
  - Файл: `src/utils/movie_filter.py` (строка 81).
  - Что сделать:
    - читать `rating.filmCritics` (`fc`) и `votes.filmCritics`; **`0`/`None` = данных нет** (не провальная оценка);
    - при `votes.filmCritics ≥ 10`: шринк к консенсусу `s1 = base + 0.2 · (fc − base)`;
    - ступени (клампятся суммарно ±0.3): `+0.3` при `fc ≥ 8 и votes ≥ 20` («Certified Fresh»); `−0.3` при `fc ≤ 3 и votes ≥ 20` (критический провал);
    - итог: `score = clamp(s1 + tier, 0, 10)`.
  - Критерий приёмки: без `fc` формула **вырождается ровно в текущее поведение** (обратная совместимость); единицы измерения не смешиваются (fc — шкала 0–10).

- [x] **A2. Поля критиков в итоговом словаре фильма** — 1–2 ч; зависит: A1
  - Файл: `src/recommendation_engine.py`, `_format_movies_list`.
  - Что сделать: добавить `critics_rating` + `critics_votes` рядом с `rating_source` (пока без вывода в UI — данные для A3/B6/B7 и отладки).
  - Критерий приёмки: поля присутствуют в dict при наличии в API-ответе, `None` при отсутствии.

- [x] **A3. Триггер «одобрено критиками» в поиске** — 0.5 дня; зависит: A1
  - Файлы: `src/kinopoisk_client.py` (`search_movies`), `src/recommendation_engine.py`, `src/intent_classifier.py` (fallback-regex), `src/prompts/parameter_extraction_prompt.txt`.
  - Что сделать: слово «критик» в запросе →
    - API-параметры: `sortField=rating.filmCritics`, `sortType=-1`, `notNullFields=rating.filmCritics`, `votes.filmCritics=10-100000` (фильтр голосов работает);
    - локальный порог `filmCritics ≥ 7` — **диапазонный фильтр по рейтингу API молча игнорирует (подтверждённый баг), только локально**;
    - новый параметр извлечения (напр. `critics_approved: bool`) в промпт и fallback-классификатор.
  - Критерий приёмки: «фильмы одобренные критиками» → выдача отсортирована по fc, без мусора «10.0 при 1–2 рецензиях»; остальные запросы не затронуты.

- [x] **A4. Верификация фазы 0** — 2–3 ч; зависит: A1–A3
  - Расширить `tests/` (test_dialogue_manager.py / новые test_movie_filter.py): `fc=0` → нет данных; шринк и ступени; обратная совместимость; триггер «критик».
  - Прогнать ruff/mypy/pytest + локальный запуск бота (`python src\telegram_bot.py`, `PYTHONIOENCODING=utf-8`), ручной диалог: «топ драм», «фильмы одобренные критиками», «расскажи о фильме Побег из Шоушенка» (ожидание: fc 8.4/147 голосов учтён).
  - Критерий приёмки: все проверки зелёные; поведение без `fc` не изменилось.

## Epic B (P1): настоящий Tomatometer через OMDb API

> Ценность: «🍅 91%» — узнаваемый бейдж качества + мягкий буст в ранжировании. Стоимость: 2–3 дня, $0–1/мес. **Гейт: старт только после зелёной фазы 0 (A1–A4).**

- [x] **B1. Лицензия и конфигурация (блокер для остальных B)** — 1 ч; зависит: A4
  - Предусловие: OMDB_API_KEY уже добавлен пользователем в .env и .env.production
  - Проверить: OMDb — **CC BY-NC 4.0, только некоммерческое использование**. Для MVP без монетизации — приемлемо; при коммерциализации RT-лицензия от ~$60k/год = фактически отказ от RT. Зафиксировать решение комментарием в `.env.example`.
  - Добавить: `OMDB_API_KEY`, `ENABLE_RT_SCORES=true/false` в `.env.example`; без ключа/при `false` весь Epic B выключен (feature flag).
  - Получить свой ключ и **проверить наличие RT в ответе free-ключа** (пробел из исследования).
  - Критерий приёмки: решение зафиксировано; feature flag выключает Epic B без регрессий.

- [x] **B2. Модуль `src/omdb_client.py`** — 0.5 дня; зависит: B1
  - По образцу `kinopoisk_client.py`: aiohttp + tenacity, таймаут 5–10 с.
  - `GET https://www.omdbapi.com/?i={imdb_id}&apikey=...`; парсинг `Ratings[]` → `rt_score: int|None` («91%» → 91), `metascore`.
  - `Response != "True"` / нет RT / любая ошибка → `None`, **без исключений**.
  - Критерий приёмки: юнит-тесты на парсинг (есть RT / нет RT / ошибка) без сети.

- [x] **B3. Join-ключ IMDb ID** — 1–2 ч; зависит: B1
  - Файл: `src/kinopoisk_client.py` — добавить `externalId` в `selectFields` в трёх местах (строки 79-81, 129-131, 173-175).
  - Покрытие `externalId.imdb` — 69% базы; у фильмов без IMDb ID RT-бейджа просто нет (незаметная деградация).
  - Критерий приёмки: `externalId.imdb` присутствует в dict фильма при наличии.

- [x] **B4. Кэш RT-скоров в PostgreSQL** — 0.5 дня; зависит: B1
  - Таблица `rt_scores (imdb_id TEXT PK, rt_score SMALLINT NULL, metascore SMALLINT, fetched_at TIMESTAMPTZ DEFAULT now())`; TTL 30–90 дней; **обязательное отрицательное кэширование** (NULL = «нет данных», повторно не дёргаем).
  - ⚠️ Синхронизировать схему в `src/models/database.py` **и** `init_db.py` (ловушка AGENTS.md).
  - Лимит free 1000 зап/день: кэш + 13 запросов/выдача ≈ 75 выдач/день; при росте — $1/мес → 100k/день.
  - Критерий приёмки: hit/miss/negative-кэш работают; схема идентична в обоих файлах.

- [x] **B5. Пайплайн обогащения финальных ≤13 фильмов** — 0.5 дня; зависит: B2–B4
  - Обогащать **только финальные ≤13 фильмов после `filter_movies_by_quality`** (не 250 кандидатов): `asyncio.gather` + семафор 3–5.
  - Латентность: +100–300 мс на выдачу. Любой сбой OMDb → выдача без бейджей (fail-silent).
  - Критерий приёмки: OMDb вызывается только для финала; сбой не ломает выдачу.

- [x] **B6. RT в ранжировании (буст/демотивация)** — 0.5 дня; зависит: A1, B5
  - Файлы: `src/utils/movie_filter.py`, `src/recommendation_engine.py`.
  - Формула (из исследования §4, итоговая): шринк `s2 = s1 + 0.2 · (rt/10 − s1)`; ступени `+0.3` при `rt ≥ 75`, `−0.3` при `rt ≤ 40` (суммарный кламп ±0.3 с A1); **нормализация rt/10 обязательна** (процент ≠ шкала 0–10).
  - **Не применять** в ветке `is_russian_search` и без IMDb ID.
  - Критерий приёмки: без `rt` поведение = фазе 0; российская ветка не затронута.

- [x] **B7. Бейдж «🍅 91%» в списках и карточках** — 2–3 ч; зависит: B5
  - `dialogue_manager.py`: «🍅 91%» рядом с рейтингом в `_generate_list_response` и в карточке info-интента; только когда `rt_score` есть.
  - Согласовать с эмодзи-гайдлайном из `docs/research/research_uiux_telegram.md` (🍅 = один смысл «одобрено критиками»).
  - Критерий приёмки: бейдж виден при наличии rt_score и отсутствует без него.

- [x] **B8. Верификация фазы 1** — 0.5 дня; зависит: B5–B7

  - Прогнать ruff/mypy/pytest + локальный запуск; все проверки зелёные.
  - Критерий приёмки: зелёные ruff/mypy/pytest; flag off даёт поведение фазы 0.

## Риски и ограничения (учесть при реализации)

1. **Баги kinopoisk.dev**: диапазонный фильтр `rating.filmCritics` молча игнорируется (фильтровать локально); сортировка по fc без порога голосов даёт мусор (обязателен `votes ≥ 5–10`); `fc = 0` трактовать как «нет данных».
2. **Покрытие**: полезный критический сигнал — ~2% базы (21k фильмов); RT-бейдж будет у меньшинства выдач — это нормально, деградация незаметна.
3. **Лицензия OMDb**: CC BY-NC 4.0 — блок на коммерциализацию; зафиксировать до начала B (B1).
4. **Российский контент**: Tomatometer почти всегда отсутствует — ветка `is_russian_search` остаётся на КП.
5. **In-memory кэш не переживает рестарт** — кэш RT только в PostgreSQL (B4).
