## Why

Рабочая копия проекта неработоспособна: незавершённый переход импортов
ломает оба способа запуска (`python -m src.telegram_bot` и
`python src\telegram_bot.py`), а относительный импорт в
`recommendation_engine.py:271` приводит к ImportError на каждой выдаче
рекомендаций (проверено запуском). Продакшен работает на устаревшем
образе 1.0.3, и новый образ из текущего кода не соберётся. Дополнительно
накоплены проблемы надёжности и качества: in-memory состояние, отсутствие
тестов и CI, дублирование кода и моделей БД, слабости безопасности.
Нужно поэтапно вернуть проект в работоспособное и сопровождаемое состояние.

## What Changes

Фаза 0 — восстановление работоспособности:

- Исправить относительный импорт в `recommendation_engine.py`
  (использовать плоский импорт `utils.movie_filter`).
- Завершить переход на плоские импорты в `src/` и согласовать с ним
  CMD в `Dockerfile` (запуск бота без `-m`).
- Зафиксировать в git незакоммиченную работу над админ-панелью.
- Проверить запуск бота (диалог) и веба (`GET /health`).

Фаза 1 — надёжность:

- Сессии диалога и кэш поиска: изолировать по пользователям и сделать
  переживающими рестарт и общими для нескольких воркеров.
- Режим `BOT_MODE=webhook`: реализовать корректно (обработка очереди
  обновлений) либо удалить режим и его заготовки.
- Ретраи внешних API (GigaChat, Kinopoisk) — только для временных
  ошибок (429/5xx, сетевые).
- `monitoring.py`: удалить либо реализовать `/metrics` через фабрику
  приложения и добавить `prometheus_client` в зависимости.

Фаза 2 — качество:

- Тесты на ключевую логику без внешних API (`dialogue_manager`,
  `intent_classifier`, `movie_filter`).
- ruff + mypy и CI на тесты и сборку образа.
- Единая инициализация БД без дублирования моделей (и миграции).
- Текущий год — один источник вместо хардкода в 5+ местах.
- Аудит `requirements.txt` и `config.py`: убрать неиспользуемое.
- Логирование: именованные логгеры, предсказуемые пути файлов.

Фаза 3 — гигиена и безопасность:

- Пароль админа обязателен из env, без вывода в консоль и без
  дефолтного значения в проде; секретный ключ Flask — только из env.
- `debug=True` — только вне продакшена.
- Переписать README, актуализировать `docs/`, удалить легаси
  (`data/processed/`, `models/movie.py`, `utils/code_collector.py`).

## Capabilities

### New Capabilities

- `dialogue-session-state`: состояние диалога пользователя (последние
  рекомендации, параметры поиска, кэш выдачи) сохраняется после рестарта
  приложения и доступно при нескольких рабочих процессах.
- `admin-security`: создание учётной записи администратора и обработка
  секретов админ-панели (обязательные значения из окружения, запрет
  дефолтов и вывода паролей).

### Modified Capabilities

Нет — `openspec/specs/` пока пуст, это первые спецификации проекта.

## Не входит в изменение

- Изменение логики рекомендаций: словари «настроение → жанры»,
  фильтры качества, правила ранжирования и пороги рейтингов.
- Изменение промптов LLM и набора интентов (кроме приведения промпта
  в соответствие с кодом, если интенты `newer`/`older` решено не
  реализовывать — тогда они удаляются из промпта).
- Новые пользовательские функции бота и веб-чата.
- Переезд на другой источник данных (остаётся Kinopoisk API).
- Изменение схемы деплоя (по-прежнему: сборка локально → реестр
  cloud.ru → VM), кроме подъёма тега образа.

## Impact

- Код: все модули `src/` (импорты), `Dockerfile`, `init_db.py`,
  `log_setup.py`, `requirements.txt`, `config.py`, `monitoring.py`,
  `session_manager.py`, `movie_agent.py`.
- Зависимости: возможны `redis` (если выбран как хранилище сессий),
  `prometheus_client` (если `/metrics` реализуется), `pytest`, `ruff`,
  `mypy` (dev); удаление неиспользуемых `pandas`, `numpy`, `requests`.
- Деплой: новый тег образа в `docker-compose`; процедура инициализации
  БД меняется (единая точка входа), требуется перезапуск сервиса.
- Документация: README, `docs/`, `openspec/config.yaml` (уже обновлён).
- Безопасность: при деплое обязателен `ADMIN_PASSWORD` в окружении.
