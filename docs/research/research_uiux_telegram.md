# Исследование: UI/UX Kinobot и поведение пользователей Telegram при выборе фильмов

*Дата: 2026-09-08 | Источников: 20 | Достоверность: средняя-высокая (аудит кода — высокая; рыночные данные — по cited-источникам)*

## Executive Summary

1. **Аудит кода**: бот общается через постоянное reply-меню из 6 кнопок + свободный текст; списки фильмов выдаются нумерованным текстом (название, год, ⭐рейтинг) со столбцом inline-кнопок «Подробнее: {title}» (до 13 штук); карточка фильма приходит 2–3 отдельными сообщениями (текст + постер). Ряд полей (`kinopoisk_url`, `country`, `rating_source`) вычисляются, но не показываются. Пагинации, редактирования сообщений, трейлеров, реакций нет.
2. **Поведение в Telegram**: аудитория 1 млрд MAU / 500 млн DAU, средний пользователь открывает приложение ~21 раз в день и проводит в нём 40+ минут; ~50% взаимодействуют с Mini Apps. Мнение о полезности бота формируется за первые 3 взаимодействия. Ввод текста на мобильном — высокое трение, тап по кнопке — низкое.
3. **Поведение при выборе фильма**: «усталость от выбора» — американцы тратят ~110 часов в год на поиск что посмотреть; 75% ценят персональные рекомендации, но >50% перегружены объёмом выдачи. Порог отказа — 2–3 минуты без результата. Главные источники открытий: соцсети (83,6%) и друзья/сарафан (76%, YouGov: 57% по 17 рынкам), специализированные приложения — лишь 7,3%. 49,8% ведут списки «что посмотреть» в заметках телефона. Ключевые факторы выбора фильма: жанр, сарафан/отзывы, актёры и режиссёр, страна, основанность на реальных событиях.
4. **Визуальное оформление**: язык эмодзи сместился — 😭 обогнал 😂/🤣 (Google/Gboard 2025, 665 млн эмодзи), 😂 воспринимается молодёжью как «устаревший», 👍 и 🙂 несут пассивно-агрессивный оттенок, 🗿 вырос с 482-го на 33-е место. Для бота безопаснее «предметные» эмодзи с одной закреплённой функцией (🎬⭐🏆), чем «лицевые». Telegram Bot API 9.4 добавил цветные кнопки (primary/success/danger) и кастом-эмодзи-иконки на кнопках; HTML-форматирование поддерживает спойлеры и раскрываемые цитаты — но PTB 22.5 (версия проекта) стили кнопок ещё не поддерживает (issue #5136).
5. **Главный вывод**: ниша бота — не «ещё одна база фильмов», а «быстрое решение за 1–2 тапа». Рекомендации ниже ранжированы по этому принципу: меньше вариантов в выдаче, больше контекста в карточке (постер+рейтинг+ссылка одним сообщением), редактирование сообщений вместо новых, кнопка «Сохранить в список», кнопки-ссылки на Кинопоиск.

## 1. Аудит текущего состояния (как бот общается сейчас)

### 1.1. Точки входа

- Команды: `/start`, `/help`, `/movie <название>`, `/top`, `/genre`, `/mood` (`src/telegram_bot.py:262-276`).
- **Команды не зарегистрированы через BotFather/setMyCommands** — в меню клиента их нет, пользователь узнаёт о них только из `/help`.
- `/start` — длинное приветствие (12 строк) + постоянное reply-меню `get_main_menu()` (`telegram_bot.py:34-41, 51-70`): «🎭 Фильм по настроению / 🏆 Топ фильмов», «🎬 Поиск по жанру», «🔄 Другие варианты / 💡 Помощь», «🆕 Новый диалог».
- Диспетчеризация кнопок — по **точному совпадению текста** (`telegram_bot.py:135-188`): ручной ввод «топ фильмов» с другим регистром уходит в LLM-пайплайн, а не в меню.

### 1.2. Выдача результатов (список)

`_generate_list_response` (`src/dialogue_manager.py:530-543`):

```
<strong>Топ фильмов в жанре комедия 2020-х годов:</strong>
1. <strong>Название</strong> (2021) — ⭐ 7.8
...
```

Плюс вертикальный столбец inline-кнопок `Подробнее: {title}` (по одной на ряд, до 13).

Проблемы:
- **Нет жанра, страны, источника рейтинга** в списке — пользователь не может отсеять, не кликнув 13 раз.
- `rating_source` (IMDb/КП) и `kinopoisk_url` вычисляются (`recommendation_engine.py:310-324`), но **нигде не выводятся**.
- Текст кнопки не обрезается: длинное название > 64 символов → ошибка отправки сообщения (лимит Telegram на caption кнопки).
- **Несогласованный лимит**: initial готовит 13 фильмов, similar/alternative показывают только 8 (дефолт `_generate_list_response(limit=8)`), в сессию пишутся 13.
- Постеров в списке нет.

### 1.3. Карточка фильма

- Текст `🎬 <strong>Название</strong> (год) — жанр с рейтингом X.\nОписание(≤500 зн.)` (`dialogue_manager.py:545-551`) + постер **отдельным сообщением** (`telegram_bot.py:121-127`).
- Callback «Подробнее» делает свежий запрос к API Кинопоиска и **отвечает новыми сообщениями**, не редактируя список (`telegram_bot.py:210-258`) — чат засоряется, «Vertical sprawl».
- Нет кнопок «Похожие», «На Кинопоиск», «Сохранить», «Назад к списку».

### 1.4. Диалоговый флоу

- Пайплайн: санация → guardrails (блокер офтопика/длины/prompt-атак, `src/guardrails.py`) → LLM-классификация интента (initial/info/similar/alternative/offtopic) → ветвление (`dialogue_manager.py:57-101`).
- Контекст сессии (`last_movies`, `last_params`) сохраняется в PostgreSQL/in-memory, TTL 3600 с (`session_manager.py`).
- Индикатор `typing` используется (`telegram_bot.py:112`) — хорошо.
- Отказы при офтопике дружелюбны, с примерами запросов (`guardrails.py:24-31`) — хорошо.
- Смешение parse_mode: HTML везде, кроме двух сообщений настроения (Markdown) — риски расхождения отображения.

### 1.5. Мёртвый код / рассинхрон

- `src/prompts/single_movie_response_prompt.txt` не загружается нигде.
- Веб `index.html` обрабатывает клики по `.movie-item` → `/movie-details`, но роута в `app.py` нет, разметка не генерируется.
- `UserSession.dialogue_history` объявлено, но не заполняется.

### 2.2. UX-паттерны ботов (сводка лучших практик)

Источники: [TeleSuite UX Guide](https://telesuite.io/blog/telegram-bot-design-best-practices-ux-guide), [botnamefinder Inline Keyboard Guide](https://botnamefinder.com/blog/telegram-inline-keyboard-builder-guide), [IxDF: Progressive Disclosure](https://ixdf.org/literature/topics/progressive-disclosure), [designstudiouiux](https://www.designstudiouiux.com/blog/chatbot-ui-ux-design/).

1. **Тап вместо ввода.** Печать на мобильном — высокое трение; архитектура должна предлагать готовые варианты (decision tree из микро-коммитментов).
2. **Первые 3 взаимодействия решают.** Пользователь формирует мнение о полезности бота за первые три контакта → онбординг должен давать ценность сразу, а не инструкцию.
3. **Progressive disclosure.** Не 12 опций сразу, а 3 верхнеуровневые категории → следующий уровень после выбора. Это снижает когнитивную нагрузку (главная причина брошенных ботов).
4. **Inline-кнопки:**
   - 3–4 кнопки в ряд максимум (читаемость на мобильном);
   - эмодзи как «пространственные маркеры» в начале подписи;
   - префиксные callback-соглашения (`menu:main`, `page:2`, `info:{id}`) для маршрутизации;
   - **редактировать сообщение после тапа** (`editMessageText`/`editMessageReplyMarkup`), а не слать новое — чат остаётся чистым, ощущение «приложения»;
   - URL-кнопки — только для внешних переходов (не для внутренней навигации);
   - лимит текста кнопки — 64 символа (обрезать длинные названия).
5. **Reply-клавиатура** — для постоянных действий сессии; **inline** — для контекстных действий, привязанных к сообщению (они остаются в истории).
6. **Антипаттерн «Vertical sprawl»:** 5–6 сообщений подряд при старте → несколько уведомлений, контекст уезжает вверх. Одно сообщение = одна мысль.
7. **Ошибки никогда не должны быть генерик-сообщениями:** объяснять причину и давать кнопку с валидным примером («dead-end» ведёт к удалению бота).
8. **Mini Apps** — для каталогов с картинками, дашбордов, многошаговых форм; переход из чата нужно объяснять «bridge-сообщением». Inline-клавиатуры — для быстрых одиночных выборов.
9. **Метрики UX бота:** Time to Task Completion, Retention D7, Callback Interaction Rate (важнее MAU).

### 2.3. Визуальное оформление: эмодзи, кнопки, форматирование (тренды 2025–2026)

#### Эмодзи: что изменилось

Источники: [Google/Gboard-данные 2025 via ThePrint](https://theprint.in/feature/most-used-emoji-gen-z-google-data/3019664/) (выборка 665 млн эмодзи), [NYT Upshot, авг 2026](https://www.nytimes.com/interactive/2026/08/12/upshot/emoji-generations.html), [Fanpage Karma, 2026](https://www.fanpagekarma.com/insights/gen-z-emojis/).

- **😭 — самый используемый эмодзи в мире** (обогнал 😂 и 🤣): универсальный маркер «слишком смешно / слишком жизненно». 😂 и 🤣 молодежь считает устаревшими («кринж») — как только эмодзи массово принимают старшие, молодые переключаются на новый.
- **👍 теряет популярность** (вместо него растёт 🙏); в молодёжной среде 👍 и 🙂 читаются как **сухие или пассивно-агрессивные**. 💀 = «умираю со смеху», 🗿 — дедпан/сарказм (рост с 482-го места в 2021 до 33-го в 2025), 🔥 вытесняет 💯 у молодых, 🥀 — грусть вместо 💔.
- Топ-10 эмодзи в целом **стабилен годами** (при 3600+ доступных) — т.е. для продуктового интерфейса безопасен нейтральный базовый набор, а не погоня за мемами.
- **Эмодзи = культурный код, а не декор.** Брендам рекомендуют трёхкатегорийный гайдлайн: (1) эмодзи, соответствующие голосу бренда; (2) замеченные в комьюнити, но пока не используемые; (3) сознательно избегаемые. Чек-лист перед использованием: organic ли он у аудитории, ясен ли смысл с иронией, подходит ли тону, не затёрт ли тренд, работает ли сообщение без эмодзи.
- **Доступность** ([BOIA](https://www.boia.org/blog/emojis-and-web-accessibility-best-practices), [UX Content Collective](https://uxcontent.com/accessible-content-design-for-emojis/)): скринридеры озвучивают эмодзи — использовать экономно, в конце фразы, без повторов; не заменять эмодзи текстовый смысл; иконка-кнопка без подписи недоступна.

#### Кнопки: внешний вид

- **Bot API 9.4 (2025): цветные кнопки и иконки.** Поля `style` (Danger — красный, Success — зелёный, Primary — синий) и `icon` (ID кастом-эмодзи) работают и для reply-, и для inline-клавиатур ([telegrambots/book](https://github.com/telegrambots/book/blob/main/src/2/reply-markup.md), [core.telegram.org keyboardButtonStyle](https://core.telegram.org/constructor/keyboardButtonStyle)).
- ⚠️ **python-telegram-bot 22.5 (версия проекта) эти поля ещё не поддерживает** — открытый [issue #5136](https://github.com/python-telegram-bot/python-telegram-bot/issues/5136). Обходной путь: `api_kwargs`/сырой HTTP-вызов; либо дождаться релиза PTB.
- Кастомные (анимированные) эмодзи в сообщениях бота — с февраля 2026 разрешены, **если у владельца бота есть Telegram Premium** (только private/group/supergroup, не каналы) ([api-changelog](https://core.telegram.org/bots/api-changelog), [PTB discussion #3960](https://github.com/python-telegram-bot/python-telegram-bot/discussions/3960)).
- Базовые правила подписей кнопок ([botnamefinder](https://botnamefinder.com/blog/telegram-inline-keyboard-builder-guide), [Balsamiq](https://balsamiq.com/blog/button-design-best-practices/)): эмодзи в начале подписи как визуальный маркер (иконка считывается быстрее текста: «📊 Stats» быстрее «Посмотреть статистику»), один стиль на тип действия (последовательность важнее красоты), глаголы действия в подписи, 3–4 кнопки в ряд, ≤64 символов.

#### Форматирование сообщений: неиспользуемые возможности

Полный список HTML-сущностей Bot API ([grammY ParseMode](https://grammy.dev/ref/types/parsemode)):

| Возможность | Синтаксис (HTML) | Применение в Kinobot |
|---|---|---|
| Жирный/курсив/подчёркнутый/зачёркнутый | `<b> <i> <u> <s>` | используется частично (`<strong>`, `<i>`) |
| **Спойлер** | `<span class="tg-spoiler">` | идеален для сюжетных поворотов в описании («что будет — под катом») |
| **Раскрываемая цитата** | `<blockquote expandable>` | описание фильма сворачивается в компактный блок — прогрессивное раскрытие внутри одного сообщения |
| Цитата | `<blockquote>` | для «вердикта»/логлайна |
| Инлайн-ссылка | `<a href>` | название фильма → Кинопоиск (поле уже есть) |
| Кастом-эмодзи | `<tg-emoji emoji-id>` | требует Premium владельца (см. выше) |
| Код/прекод | `<code> <pre>` | не релевантно |

Проектом используется только bold/italic/code — спойлеры и раскрываемые цитаты не задействованы, хотя тематически боту про кино подходят как никому.

## 3. Исследование: поведение пользователей при выборе фильма

### 3.1. Decision fatigue — главная боль

Источник: [UserTesting/Talker Research, ноябрь 2024, n=4000 (US/AU/UK)](https://www.usertesting.com/resources/reports/stream-fatigue-goes-global):

- Американцы тратят **~110 часов в год (≈5 суток)** только на выбор что посмотреть.
- **75%** ценят персонализированные рекомендации алгоритмов, но **>50%** признаются, что объём выдачи их перегружает.
- Почти **1 из 5** американцев: найти что посмотреть сейчас сложнее, чем 10 лет назад.
- В Австралии — **16 минут в день** на выбор; 52% называют интуитивную навигацию важным фактором подписки.
- Цитата (Bobby Meixner, UserTesting): «Стриминг сместился от решения проблемы доступа к созданию проблемы обнаружения».

Дополнительно ([Medium: Netflix Syndrome UX case study](https://medium.com/@aryagawade2001/netflix-syndrome-a-ux-ui-case-study-on-the-paradox-of-choice-410a062cc403)): закон Хика — чем больше опций, дольше выбор; «принцип наименьшего усилия» — пользователь выбирает путь минимального сопротивления.

### 3.2. Где ищут фильмы и кому доверяют

Источник: [MovieCrush user research, KSE 2026, n=262 + 5 интервью + 13 тестеров](https://kse.ua/wp-content/uploads/2026/07/anastasiia_syvak-1.pdf) (выборка 18–24, нерепрезентативна — product-segment fit):

- Источники рекомендаций: **соцсети 83,6%**, **друзья/родные 76%**, стриминг-алгоритмы 33,6%, IMDb/сайты рейтингов 33,2%, **специализированные приложения — лишь 7,3%**.
- **49,8%** ведут watchlist **в заметках телефона** (и все называют это неудобным), 24,9% — никак не отслеживают, 19,8% — Letterboxd/IMDb, 7,6% — сохранения в TikTok/Instagram.
- Поиск занимает **от 5 минут до 3 часов**; порог отказа — **2–3 минуты без результата** («желание смотреть пропадает полностью»).
- **Фильтры — самый частый запрос** в интервью («чем больше фильтров, тем быстрее найдёшь»).
- За что готовы платить: **AI-рекомендации 42%**, личная статистика/Wrapped 35,9%.
- Социальные функции: «видеть, что смотрят и как оценивают друзья» — 48,9%.
- Тестеры больше всего хвалили: **рейтинг прямо на постере** (не открывая карточку), Wrapped-аналитику, страницу актёра с фильмографией.
- Самый частый запрос на улучшение: **«где смотреть» (стриминги + прямая ссылка)**.
- Конкурентные боли: алгоритмы рекомендуют популярное, а не персональное; нет сериалов/аниме; нет статистики просмотров.

Источник: [YouGov, 17 рынков, сентябрь 2023](https://yougov.com/articles/48043-a-majority-of-viewers-rely-on-word-of-mouth-to-make-cinema-and-tv-show-choices): **сарафанное радио помогает выбирать кино 57%** (16% «очень сильно» + 41% «заметно»); женщины полагаются чуть чаще мужчин.

### 3.3. Факторы выбора фильма (академические данные)

[Gazley et al., «Understanding preferences for motion pictures», Journal of Business Research 64(8), 2011](https://www.sciencedirect.com/science/article/abs/pii/S014829631000192X): значимые факторы — **жанр, основанность на реальных событиях, критические отзывы, сарафан, страна происхождения, звёзды и режиссёр**.

[Offscreen: Going to the Movies](https://offscreen.com/view/going_to_the_movies): исследованные медиумы влияния — звёзды, режиссёры, трейлеры, реклама, сарафан.

### 3.4. Конкурент-референс (русскоязычный)

[@mozinga_bot (vc.ru, 2020)](https://vc.ru/tribuna/136505-telegram-bot-kotoryi-podskazhet-kakoi-film-posmotret): радикальный минимализм — **две кнопки** («Дай фильм», «Дай похожий»), контент по запросу без категорий/жанров/годов, **трейлер внутри чата** (Telegra.ph-превью), карточка фильма в одном сообщении. Позиционирование: «как если бы порекомендовал друг». Комментарии читателей сразу просят рейтинг КП/IMDb и ссылку на фильм — подтверждает набор обязательных полей карточки.

## 4. Gap-анализ: Kinobot vs исследования

| Инсайт исследования | Текущее состояние бота | Разрыв |
|---|---|---|
| Ценность за первые 3 взаимодействия | /start = 12 строк текста, ценность только после запроса | Онбординг учит, а не показывает |
| Decision fatigue: меньше опций — быстрее выбор | До 13 фильмов списком + 13 кнопок в столбик | Перегруз выдачей и кнопками |
| Порог отказа 2–3 минуты | Каждый «Подробнее» — новый запрос к API + 2 новых сообщения | Замедление вместо ускорения |
| Факторы выбора: жанр, актёры, страна, рейтинг | В списке только название/год/рейтинг | Нет данных для быстрого отсева |
| Рейтинг прямо на постере (топ-фича у тестеров) | Постер только отдельным сообщением, без рейтинга | Карточка не сканируется глазами |
| Сарафан/ссылки: 76% ищут через друзей | kinopoisk_url вычисляется, но не показывается; шаринга нет | Упущен виральный канал |
| 49,8% ведут watchlist в заметках | Функции «сохранить фильм» нет | Незакрытая потребность |
| «Где смотреть» — топ-запрос | Нет | Незакрытая потребность |
| Редактировать сообщения после тапа | Callback шлёт новые сообщения | Засорение чата |
| Кнопки 3–4 в ряд, ≤64 символов | 1 кнопка в ряд, без обрезки | Риск ошибок API, громоздкость |
| Wrapped-статистика: 35,9% готовы платить | Нет статистики пользователя | Упущенная возможность (данные уже копятся в админке) |
| Команды в меню клиента | setMyCommands не вызывается | Команды невидимы |
| 👍/🙂 — рискованные эмодзи для молодой аудитории | В текстах только «предметные» эмодзи (🎬⭐🏆) — ок, но в плане фидбека были 👍/👎 | Заменить на нейтральные (⭐/✅/текст) |
| Спойлер + раскрываемая цитата — тематические фичи для кинобота | Используется только bold/italic; описание фильма — открытые 500 знаков | Карточка не использует прогрессивное раскрытие |
| Цветные кнопки/иконки (Bot API 9.4) | Не используются; PTB 22.5 не поддерживает | Ждать PTB или api_kwargs |

## 5. Рекомендации по улучшению UI/UX

### P0 — быстрые победы (малые правки, большой эффект)

1. **Зарегистрировать команды через `setMyCommands`** (BotCommand-меню клиента): /start, /help, /movie, /top, /genre, /mood. Один вызов при старте приложения.
2. **Переделать список выдачи** (`dialogue_manager.py:530-543`):
   - показывать **5 фильмов вместо 8–13** (decision fatigue: меньше — лучше; закон Хика);
   - добавить в строку **жанр и источник рейтинга**: `1. <b>Название</b> (2021) · комедия, США · ⭐ 7.8 (IMDb)`;
   - сделать название **ссылкой на Кинопоиск** (`kinopoisk_url` уже есть — просто начать выводить);
   - унифицировать лимит (13 в сессии vs 8 на экране — рассинхрон).
3. **Компактные inline-кнопки вместо столбца**: нумерованные кнопки `1️⃣ 2️⃣ 3️⃣ 4️⃣ 5️⃣` по 3–4 в ряд + ряд навигации `⬅️ Назад | 🔄 Ещё | 🎲 Случайный`. Текст кнопки ≤64 символов — обрезать названия (сейчас — потенциальная ошибка отправки).
4. **Карточка одним сообщением**: `reply_photo(photo=poster_url, caption=...)` вместо «текст + отдельное фото». В caption: постер-заголовок, год, жанр, страна, рейтинг с источником, описание ≤1024 знаков (лимит caption), inline-кнопки под фото: `🔗 Кинопоиск` (URL) | `🎬 Похожие` (callback) | `📌 Сохранить` (callback).
5. **Редактировать сообщение при callback** (`editMessageText`) вместо отправки нового + кнопка «⬅️ К списку» — чистая история, app-like ощущение.
6. **Убрать смешение parse_mode**: везде HTML (два Markdown-сообщения в /genre и /mood — перевести).
7. **Современное форматирование карточки** (доступно уже сейчас, PTB 22.5 поддерживает):
   - описание фильма — в `<blockquote expandable>` (раскрываемая цитата): карточка становится компактной, длинный синопсис не простынюет чат — прогрессивное раскрытие внутри одного сообщения;
   - сюжетные повороты в описании — в `<span class="tg-spoiler">` (тематическая фича для кинобота: «интрига под спойлером»);
   - логлайн/вердикт бота — одной строкой жирным перед цитатой.

### P1 — усиление диалога и удержание

8. **Онбординг «ценность сразу»**: сократить /start до 3–4 строк и в первом же сообщении дать тап-пример («🎲 Случайный фильм вечера» — мгновенный результат без ввода текста). Первые 3 взаимодействия формируют мнение о боте.
9. **Контекстные quick replies под каждым списком**: «🔄 Другие варианты», «🎬 Похожие на №1», «⬇️ Ещё 5» — сейчас «Другие варианты» есть только в постоянном меню, без привязки к контексту.
10. **Пагинация «Ещё 5»** вместо альтернативного интента: хранить смещение в callback_data (`page:2:{hash}`) — пользователь листает выдачу тапами.
11. **Фича «📌 Мой список» (watchlist)**: 49,8% целевой аудитории ведут списки в заметках телефона. Кнопка «Сохранить» в карточке + команда/кнопка «📌 Мой список» + возможность удалить. Хранение — уже имеющийся PostgreSQL.
12. **Обратная связь на рекомендацию — нейтральными эмодзи**: под карточкой кнопки **«⭐ Оценить» / «✅ Смотрел» / «❌ Не моё»** вместо 👍/👎 — «палец вверх» молодёжью читается как сухой/пассивно-агрессивный, а оценка звёздами ещё и даёт данные для персонализации (боль №1 у конкурентов: «рекомендуют популярное, а не мне»).
13. **Эмодзи-гайдлайн бота** (правило «1 эмодзи = 1 смысл», зафиксировать в `src/prompts/` или отдельном модуле):
    - ядро (уже используется — оставить): 🎬 фильм, 📺 сериал, ⭐ рейтинг, 🏆 топ, 🎭 настроение, 🔄 другие варианты, 💡 помощь, 🆕 сброс, ⚠️ ошибка;
    - добавить: 🎲 случайный выбор, 🔥 рейтинг ≥8.0 в списках (визуальный якорь качества, молодой аналог 💯), ✨ новинки/премьеры;
    - **избегать**: 😂🤣 (маркер «устаревшего» бренда у аудитории <25), 🙂 и 👍 (пассивно-агрессивный оттенок), 💀🗿 и прочие мем-коды (быстро устаревают, риск выглядеть «кринжово» — брендам рекомендуют их только наблюдать, не использовать);
    - без повторов и «эмодзи-простыней»: не более 1 эмодзи на строку списка, эмодзи — в начале или в конце фразы, не в середине (доступность: скринридеры озвучивают каждый).
14. **Дружелюбные ошибки с выходом**: вместо «⚠️ Произошла ошибка» — объяснение + кнопка с валидным примером (dead-end = удаление бота).
15. **Точный матч текстов кнопок → callback_data**: диспетчеризация reply-меню по точному совпадению строк хрупка; перевести меню на inline-кнопки с префиксными callback (`menu:mood`, `top:50`).

### P2 — дифференциация (требуют данных/инфраструктуры)

16. **Цветные кнопки и иконки (Bot API 9.4)**: `style` (primary/success/danger) + `icon` (кастом-эмодзи) для reply- и inline-клавиатур — напр. «🗑 Удалить из списка» красным (danger), «✅ Сохранено» зелёным (success). ⚠️ PTB 22.5 не поддерживает (issue #5136) — ждать релиз или слать через `api_kwargs`/сырой запрос; проверить отображение на старых клиентах (деградация должна быть graceful).
17. **Кастомные анимированные эмодзи в сообщениях** (`<tg-emoji emoji-id="...">`): требуют Telegram Premium у владельца бота (changelog 09.02.2026; только private/group/supergroup). Умеренно: фирменная анимированная 🎬 в заголовках — запоминающийся штрих, но каждый эмодзи озвучивается скринридерами.
18. **Трейлеры в чате**: Kinopoisk API (api.kinopoisk.dev) отдаёт `videos.trailers` — добавлять URL трейлера в карточку (ссылка-кнопка или link preview). У конкурента mozinga это ключевая фича; трейлеры — один из значимых факторов выбора.
19. **«Где смотреть»**: самый частый запрос тестеров MovieCrush. Минимум — ссылка на страницу Кинопоиска (там есть провайдеры); максимум — агрегация по подпискам пользователя.
20. **Персональная статистика («кино-Wrapped»)**: 35,9% готовы платить за статистику; у бота уже копятся запросы в PostgreSQL (админка/статистика). Ежемесячная сводка: «Вы спросили 42 рекомендации, любимый жанр — триллер».
21. **Media group для топов**: /top 50 — альбом из 10 постеров с рейтингом в подписи вместо текстового списка (визуальный каталог = то, за что хвалили «рейтинг на постере»).
22. **Mini App для визуального каталога** (долгосрочно): ~50% пользователей Telegram уже взаимодействовали с TMA; entertainment-категория — 9M MAU. Веб-морда (`src/app.py` + templates) частично существует — можно переиспользовать как Telegram WebApp с bridge-кнопкой в меню. Преждевременно до P0/P1.
23. **Почистить мёртвый код**: неиспользуемый `single_movie_response_prompt.txt`, несуществующий роут `/movie-details` в index.html, незаполняемый `dialogue_history` — либо реализовать, либо удалить.

### Метрики для проверки эффекта

- **Time to first result** (цель: <10 с от первого тапа);
- **Callback interaction rate** (доля пользователей, кликнувших «Подробнее»/«Ещё»);
- **Retention D7**;
- доля сессий, закончившихся сохранением в watchlist или переходом на Кинопоиск (прокси «рекомендация сработала»).

## Методология

Выполнено ~12 поисковых запросов (web + research + developer), прочитано полностью 8 источников, PDF-исследование (n=262) разобрано субагентом. Параллельно проведён аудит кодовой базы (`src/telegram_bot.py`, `src/dialogue_manager.py`, `src/session_manager.py`, `src/guardrails.py`, `src/recommendation_engine.py`, `src/prompts/`, `src/templates/`); версия python-telegram-bot проверена локально (22.5, поля style/icon отсутствуют). Ограничения: статистика Telegram — из вторичных маркетинговых отчётов (оценки различаются: TMA MAU 150M vs 400–500M в разных источниках — указан консервативный диапазон PropellerAds); MovieCrush — нерепрезентативная выборка 18–24; YouGov-данные 2023 года; эмодзи-тренды быстро меняются (данные Google — 2025, NYT — авг 2026), мем-эмодзи приводятся как «избегать», а не как инструкция к применению.
