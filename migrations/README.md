# Миграции БД (Alembic) — kinobot

Каталог содержит миграции схемы БД. Единственный источник схемы — модели
`src/models/database.py` (`db.metadata`); `migrations/env.py` использует их
метаданные для autogenerate. URL подключения берётся из переменной окружения
`DATABASE_URL` (fallback — локальный PostgreSQL
`postgresql://postgres:postgres@localhost:5432/kinobot_db`, константа
`src/db_bootstrap.DEFAULT_DATABASE_URL`). В `alembic.ini` боевой URL НЕ
хранится.

## ПОЛИТИКА СОХРАННОСТИ ДАННЫХ (обязательна)

- **additive-first**: baseline и все последующие автогенерируемые миграции
  добавляют новое — таблицы, колонки, индексы, ограничения. Прод-БД содержит
  данные пользователей (watchlist, фидбек, статистика) — терять их нельзя.
- **Разрушающие операции запрещены «в лоб»**: `drop_table`, `drop_column`,
  изменение типа колонки (`alter type`) допускаются ТОЛЬКО через ручное ревью
  и отдельную миграцию с явным бэкапом БД перед накатом
  (`pg_dump ... | gzip`, порядок появится в T12).
- Autogenerate может предложить drop при переименовании/сужении типа — такие
  места вычищаются вручную: переименование оформляется как
  `op.alter_column`/перенос данных, а не drop+create.
- `downgrade()` ревизии `0001_initial` содержит `drop_table` — **вручную на
  проде НЕ запускать** (уничтожит данные).

## Основные команды (из корня репозитория)

Windows: alembic читает `alembic.ini` в кодировке локали (cp1251), а файл
хранится в UTF-8 (русские комментарии) — запускайте команды с `PYTHONUTF8=1`
(в Linux/прод-контейнере UTF-8 читается по умолчанию, переменная не нужна).

```bash
# Новая миграция по изменениям моделей:
alembic revision --autogenerate -m "краткое описание"
# После autogenerate ОБЯЗАТЕЛЬНО прогоните линтер:
#   ruff check --fix migrations/versions/
# Пустой диф (модели == БД) оставляет в файле ревизии неиспользуемые
# импорты op/sa (F401) — поправьте их или удалите пустую ревизию.

# Накатить все миграции до последней:
alembic upgrade head

# Пометить СУЩЕСТВУЮЩУЮ БД (созданную init_db.py/create_all) без наката DDL:
alembic stamp head

# Текущая версия схемы / история:
alembic current
alembic history
```

Штатный ввод прод-БД в версионирование — `alembic stamp head` (БД уже
создана `create_all`); baseline `0001_initial` дополнительно идемпотентна:
каждый `create_table`/`create_index` обёрнут проверкой существования через
`sa.inspect(op.get_bind())`, поэтому `upgrade head` безопасен и на частично
созданной схеме.

ОГРАНИЧЕНИЕ offline-режима: guard-ы baseline (`sa.inspect`) требуют реального
подключения и работают только online — `alembic upgrade head --sql` через
`0001_initial` невозможен (NoInspectionAvailable); offline-генерация SQL
применима только к последующим ревизиям без guard-ов.

Подробная инструкция — `docs/dev_guide.md`, раздел «Миграции БД».
Регрессионные тесты миграций — задача T13; автоприменение при старте/деплое —
задача T12.
