# Эмодзи-гайдлайн бота («1 эмодзи = 1 смысл»)

Статус: нормативный документ для всех пользовательских текстов Kinobot
(кнопки, списки, карточки, ошибки, свободные ответы LLM). Источник — задача
B6 бэклога `backlog/backlog_2026-09-16_uiux_telegram.md` и отчёт
исследования UI/UX (§2.3, §5 P1.13, `docs/research/`). Регрессионная защита
запретного списка — `tests/test_emoji_guideline.py`.

## Принцип

**1 эмодзи = 1 смысл.** Каждый пользовательский эмодзи имеет единственное
закреплённое значение из таблиц ниже. Запрещено:

- использовать один и тот же эмодзи в двух разных смыслах;
- вводить новый эмодзи, не внесённый в гайдлайн;
- использовать декоративные эмодзи «для настроения» без закреплённого смысла.

## Область применения

Гайдлайн обязателен для **пользовательских текстов**: сообщения бота,
кнопки (reply и inline), списки выдачи, карточки фильмов, сообщения об
ошибках, тексты, формируемые LLM по промптам `src/prompts/*.txt`, а также
пользовательские тексты веб-интерфейса.

**Вне области**: логи разработчика (`logger.*` — там допустимы ✅ ❌ ⚠️ 🔧
как маркеры статуса), комментарии в коде, служебная документация.

## Категория «Ядро» (оставить, стабильные смыслы)

| Эмодзи | Единственный смысл | Где используется |
|--------|--------------------|------------------|
| 🎬 | фильм / киноконтент | «🎬 Поиск по жанру», «🎬 Похожие», вердикт карточки, бренд |
| 📺 | сериал | «📺 Топ 50 сериалов» и др. кнопки сериалов |
| ⭐ | зрительский рейтинг | строки выдачи и карточки («⭐ 7.8»); с B5 — «⭐ Оценить» и приглашение панели оценки |
| 🏆 | топ / рейтинг-список | «🏆 Топ фильмов», кнопки топов |
| 🎭 | настроение | «🎭 Фильм по настроению», приглашение /mood |
| 🔄 | другие варианты / повторить | «🔄 Другие варианты», повтор запроса (B7) |
| 💡 | помощь / примеры | «💡 Помощь», блок примеров запросов |
| 🆕 | сброс / новый диалог | «🆕 Новый диалог» |
| ⚠️ | ошибка / предупреждение / ограничение | сообщения об ошибках, тематические ограничения |
| 🍅 | консенсус критиков (Tomatometer) | RT-бейдж «🍅 91%» (`RT_BADGE_EMOJI`) |

## Категория «Добавить» (зарезервированные смыслы для фаз 1–2)

| Эмодзи | Единственный смысл | Статус |
|--------|--------------------|--------|
| 🎲 | случайный фильм | для кнопки «🎲 Случайный фильм» (B7 и далее) |
| 📌 | список / сохранённое | в коде с B4: «📌 Сохранить», «📌 Мой список» (watchlist) |
| 🔥 | рейтинг ≥ 8.0 | только в строках списков выдачи, не в кнопках |
| ✨ | новинки / свежие релизы | для подборок новинок |
| 📊 | персональная статистика | в коде с C5: заголовок сводки `/stats`, кнопка меню «📊 Статистика» (`menu:stats`); ни один эмодзи ядра не несёт смысла «статистика» (🏆 — топ/рейтинг-список), поэтому символ закреплён отдельно; других значений не добавлять |

## Служебные символы (закреплённые смыслы, уже в коде)

| Эмодзи | Единственный смысл | Где используется |
|--------|--------------------|------------------|
| ⬅️ | назад / к списку | «⬅️ Назад», «⬅️ К списку» |
| ⬇️ | пагинация / показать ещё | «⬇️ Ещё 5» в ряду навигации списка (B3) и списка «📌 Мой список» (B4) |
| 🔗 | внешняя ссылка | кнопка «🔗 Кинопоиск» (B4/C3) |
| ▶️ | трейлер | кнопка «▶️ Трейлер» в карточке фильма (C3, изменение add-trailer-and-provider-buttons); других значений не добавлять |
| 1️⃣…🔟 | кнопка-номер позиции выдачи | только inline-кнопки выбора, не нумерация текста (`NUMBER_BUTTON_LABELS`) |

## Допустимы с оговоркой (введены задачей B4, фактически используются с B5)

| Эмодзи | Единственный смысл | Оговорка |
|--------|--------------------|----------|
| ✅ | подтверждение действия | в коде с B4: ответ «✅ Сохранено в «Мой список»» (watchlist); с B5: реакция «✅ Смотрел» и подтверждения «✅ Сохранено.»/«✅ Оценка сброшена.» (фидбек); в логах разработчика — без ограничений |
| 🗑️ | удаление / сброс оценки | в коде с B4: кнопка «🗑️ Удалить» у элемента списка «📌 Мой список»; с B5: кнопка «🗑️ Сбросить оценку» панели оценки; других значений не добавлять |
| ❌ | отрицательная реакция «не моё» | введён B5: единственное значение — кнопка «❌ Не моё» ряда фидбека карточки (замена рискованным 👍/👎, отчёт §2.3); в текстах ответов и других кнопках не использовать; в логах разработчика — маркер статуса, без ограничений |

## Категория «Избегать» (запрещено в пользовательских текстах)

| Эмодзи | Почему запрещён |
|--------|-----------------|
| 😂 🤣 | маркер «устаревшего» бренда (данные Google 2025 / NYT 2026) |
| 🙂 👍 | считываются как пассивная агрессия |
| 💀 🗿 | мем-коды с нестабильным значением |
| прочие мем-коды и трендовые эмодзи | гонка за мемами запрещена (риск №12 бэклога): гайдлайн строится как «стабильное ядро + список избегания» |

Запретный набор (😂 🤣 🙂 👍 💀 🗿) автоматически проверяется тестом
`tests/test_emoji_guideline.py` во всех `src/**/*.py` и
`src/templates/**/*.html`. В промптах и этом документе символы перечислены
в контексте запрета — на эти файлы сканирование не распространяется.

## Правила употребления

1. **≤ 1 эмодзи на строку списка.** Исключение — строка-вердикт карточки:
   в ней допустимы функциональные маркеры данных (⭐ рейтинг, 🍅 критики),
   т.к. они несут разные закреплённые смыслы, а не декор.
2. **Позиция — начало или конец фразы**, никогда в середине предложения.
   Эмодзи в начале строки работает как маркер категории.
3. **Доступность.** Скринридеры озвучивают название каждого эмодзи
   («лицо, рыдающее от смеха»). Поэтому: не дублировать эмодзи смысл,
   уже выраженный словами; не ставить два эмодзи подряд; не использовать
   эмодзи как единственного носителя смысла (рядом всегда текстовая подпись).
4. **Кнопки.** Эмодзи — часть текста кнопки. С задачи B8 меню полностью
   inline: диспетчеризация идёт по `callback_data` (префиксы `menu:`/`top:`),
   сравнения текста сообщения с подписями кнопок из кода удалены — правка
   эмодзи в подписи больше не ломает маршрутизацию, но смысл эмодзи остаётся
   закреплённым (таблицы выше), а подписи проверяются тестами.
5. **Ошибки.** Только ⚠️ в начале текста; сообщение об ошибке обязано
   предлагать действие (кнопка 🔄 «Повторить» — задача B7).
6. **Свободные ответы LLM.** Промпты (`src/prompts/*.txt`) содержат
   инструкцию: не использовать эмодзи из списка «Избегать», соблюдать
   «1 эмодзи = 1 смысл» и правило позиции. Промпты — источник поведения
   (AGENTS.md): меняя набор эмодзи, меняйте сначала гайдлайн, потом промпты.

## Как применять (чек-лист для новой кнопки/текста)

1. Нужен ли эмодзи вообще? Текст без эмодзи — допустимая норма.
2. Есть ли у смысла эмодзи в таблицах «Ядро»/«Добавить»/«Служебные»?
   Нет — сначала добавьте строку в гайдлайн (PR), потом в код.
3. Стоит ли эмодзи в начале или конце фразы? Ровно один на строку?
4. Не дублирует ли он смысл слов рядом (скринридер прочитает оба)?

## Единая точка констант

Модуль констант эмодзи в `src/` намеренно не создавался в B6, чтобы не
конфликтовать с B8 (перевод меню на inline-кнопки). B8 реализован БЕЗ
отдельного модуля (например `src/emoji.py`): по design.md D6 изменения
`add-inline-menu-callbacks` «единая точка» — именованные константы подписей
кнопок и текстов меню в `src/telegram_bot.py` (общие для команд и
callback-маршрутов `menu:`/`top:`) плюс прецедент локальной константы
`RT_BADGE_EMOJI` в `src/dialogue_manager.py`. Источник правды о смыслах
эмодзи — этот документ; консолидация констант в единый модуль возможна
в будущем отдельной задачей.
