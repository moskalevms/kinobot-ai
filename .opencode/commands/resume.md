Режим: **RESUME**.

Дополнительно (необязательно): $ARGUMENTS

Выполни режим RESUME пайплайна `autodev-pipeline` автономно (без вопросов
человеку):

1. Прочитай чекпоинт `backlog/state/autodev-state.json`. Нет/неполный —
   восстанови контекст по артефактам: ближайший бэклог в `backlog/` с
   незакрытыми `- [ ]`, активные изменения в `openspec/changes/`, свежие отчёты
   в `docs/research/`. Ничего не найдено → отчёт «возобновлять нечего».
2. **Живой воркер**: живость = свежий heartbeat (файл `worker.heartbeat` из
   state, mtime < `StaleMin` = 10 мин) И нет финального `verdict-<ID>.json`
   (скилл, RESUME п.2) — НЕ спавнь дубль: присоединись к КОРОТКИМ проверкам
   verdict; при необходимости перезапусти detached
   `.opencode\scripts\Wait-Worker.ps1` с теми же параметрами из state
   (`-Heartbeat` = `worker.heartbeat`, `-ErrFile` = `worker.log` + `.err`,
   `-Verdict` = `verdict-<ID>.json`, `-State` = путь state), дождись финального
   вердикта и вынеси решение ПО СТАТУСУ вердикта:
   - `exited` → штатное решение по `worker_result` + отчёту
     `backlog/state/reports/` + чекбоксам; при `failed` И `last_error`
     НАЧИНАЕТСЯ с `requires operator: ` → **blocked** (не провал качества):
     НЕ ретраить перезапуском, зафиксировать в финальном отчёте и перейти к
     следующей единице (см. SKILL.md «Ожидание и вердикт» Шаг 3);
   - `killed-hang`/`killed-walltime` ИЛИ heartbeat устарел (а финального verdict
     нет) → воркер мёртв/завис, **инфраструктурный сбой** (watchdog уже убил его
     деревом): перезапуск той же единицы `attempt+1` ≤3 с паузами 30/60/120 с,
     бюджет исправлений НЕ тратится; лимит исчерпан → `status: interrupted`.
3. Если `last_error` указывает на сетевой сбой — проверь связность
   (`Invoke-WebRequest https://api.github.com -UseBasicParsing -TimeoutSec 10`);
   нет связи → ретраи с паузами 30/60/120 с (≤3), затем `status: interrupted`.
4. Сверь state с реальностью (артефакты главнее state): задача уже `- [x]` и
   `worker_result.status: completed` → следующая единица из `queue`/бэклога;
   воркер мёртв и единица не завершена → **перезапусти воркера** той же единицы
   в НОВОЙ сессии (спавн через `.opencode\scripts\Start-Worker.ps1`,
   `attempt+1` ≤3) — воркер сам продолжит с места останова по артефактам
   (OpenSpec-изменение создано → продолжать apply, НЕ propose заново;
   `fix_iterations` не обнулять); `step: archive`/`done` → только завершить
   архивацию/отчёт.
5. Продолжи цикл диспетчера режима из `mode` (MAKE-TASK — спавн
   (`Start-Worker.ps1`)/ожидание (detached `Wait-Worker.ps1` + короткие
   проверки verdict)/гейт;
   RESEARCH/BACKLOG — делегирование `task` в этой сессии) с шага `step`,
   область — `scope`. Чекпоинты обновляй на каждом переходе.
6. Идемпотентность: никаких дублей отчётов/бэклогов/изменений/правок и никаких
   дублей воркеров, пока воркер жив по heartbeat+verdict (RESUME п.2 скилла).

Финальный отчёт: с какого шага возобновлено, что сделано, результаты verifier,
вердикты reviewer, закрытые чекбоксы, где остановились и почему, готовность к
коммиту. **НЕ делать git commit/push.**
